# 病历质控新增功能：桌面 UI 审查

日期：2026-09-06。结论：**暂不通过 UI 验收**。本轮仅审查，未修改应用代码，未执行保存、签署、运行质控、批量验签等业务写入。

## 范围与方法

按用户要求忽略移动端。使用当前本地应用、合成患者数据及临床医生身份，检查 1280、1440、1920 宽度，视口高度 1000。对照 `docs/design/ui-delivery/design-system.md`，结合本轮浏览器截图、只读 DOM 边界测量及源代码检查；不是仅凭没有横向滚动条判定合格。

V = 清晰截图与 DOM 检查；D = DOM 边界检查，未保留该宽度合格截图。D 不代表完成视觉验收。

## 按优先级的问题与建议

### F01 · P1 · 门诊浮动 AI 按钮遮挡签署按钮

步骤 4，1440×1000 实测：签署按钮位于 `(1077, 946.77)`、尺寸 `312×36`；AI 按钮位于 `(1242.84, 932)`、尺寸约 `160.16×46`，重叠约 **146.16×31.23 px**。1280 截图亦可见覆盖，1920 收起 AI 面板后仍有覆盖。患者正文没有横向溢出不意味着关键动作无遮挡。

- 位置：`web/src/vue/views/OutpatientRecordPage.vue:428` 的签署按钮与 `:433` 的 `.ai-fab`；固定定位样式见 `web/src/styles.css:94`。
- 标准：设计规范第 68 行要求浮动入口不遮挡保存、签署、确认、返回。
- 建议：将入口纳入有预留空间的操作区，或为固定入口设置真实安全区域；不以单纯提高签署按钮 z-index 掩盖问题。
- 验收：三档桌面宽度、AI 展开/收起、导航展开/收起、不同滚动位置，浮动入口与关键动作边界交集均为 0；可点击区域完整。

### F02 · P2 · 质控预览贴左上角，未按对话框居中

步骤 2，加载稳定后实测弹窗为 `760×952`，`x=0、y=0、margin=0`。1440 视口若居中，水平应约为 340，而不是 0。1280、1920 同样测到左上角定位。对话框自身内容与页脚没有越过其边界，但整体位置不符合居中弹窗预期。

- 位置：`web/src/vue/components/BusinessActionDialog.vue:74`；预览 `web/src/vue/components/RecordQcPreview.vue` 虽声明 `margin:auto`，运行时未生效，须核查样式作用范围与级联。
- 建议：在对话框实际根元素上保证居中及四周安全间距；长内容仅滚动正文，保留头部关闭和底部操作。
- 验收：各桌面宽度左右留白差不超过 2px，最小外边距 24px；展开历史/汇总后不改变居中规则；回归使用共享对话框的其他页面。

### F03 · P2 · 新增质控内容将主任务推到首屏以下

步骤 3：1440 和 1920 宽度，质控面板从 y≈458 开始，高约 361；紧随其后的就诊汇总入口高 66；主诉输入框顶部约 **1040**，在高度 1000 的首屏看不到第一个可编辑字段。即使仅有 1 条警告，仍长期占用整块正文上方空间。

步骤 5：1440/1920 左右顶线均为 y=332，符合对齐；但右侧先放当前质控与汇总，再放原“质控与当前动作”，签署位置约 y=1300。1280 因主容器宽度断点切单列，质控从 y≈1057 开始，进一步拉长操作路径。单列本身是既有响应式设计，不把它独立认定为溢出 bug。

- 位置：`web/src/vue/views/RecordEditorPage.vue:180`、`web/src/vue/views/InpatientDocumentEditorPage.vue:178`；容器断点 `web/src/vue/vue-shell.css:1636` 附近。
- 标准：设计规范第 23、56 行要求质控可收起，不长期挤压正文。
- 建议：默认紧凑摘要、按需展开详情；整合住院重复质控/动作卡片，保持原有质控门禁逻辑。不要为保留三栏而缩小临床正文。
- 验收：默认进入编辑时首屏可见第一个输入区；关键保存/审签入口可直接到达；展开质控后正文宽度、焦点定位和滚动仍正常。

### F04 · P2 · 自动质控勾选框与说明文字相距过远

步骤 3、5 的宽面板中，checkbox 在最左、对应说明在最右，视觉上无法快速识别为同一控件。1920 通用编辑器尤其明显。

- 根因依据：`web/src/vue/components/RecordQcPanel.vue:44` 使用 `.qc-filter` 放 checkbox 与裸文本；第 82 行 `justify-content:space-between` 将两者拉开。
- 建议：为自动质控开关使用独立的行内 flex 分组，checkbox 与文本相邻、间距 8px；严重程度筛选仍可左右布局。
- 验收：三种编辑器及各桌面宽度下，勾选框与说明间距一致；文字换行不脱离控件；点击说明仍能切换勾选状态。

### F05 · P2 · 共享质控组件未完全遵循字体与样式规范

步骤 2–5 的规则证据、历史、安全边界说明使用 11px，低于规范中的 12px 辅助文字基线；卡片使用 14px 内边距、9px 圆角及硬编码颜色，未统一到项目 token。预览弹窗中的严重程度筛选变为上下排列，与编辑器的同一组件不同。

- 位置：`web/src/vue/components/RecordQcPanel.vue:78` 至 `:90`；`BusinessActionDialog.vue:82` 的广泛 `:deep(label)` 网格及 11px 字号覆盖需要收窄。
- 另见：住院与预览的问题正文出现 `treatment_plan` 等内部字段名，而定位按钮已中文化；属于可读性一致性问题，不是临床规则本身的准确性结论。
- 建议：复用既有字体、间距、圆角、状态色；深层表单样式仅作用于对话框自身表单；面向医生的字段名统一中文，技术证据可保留原始字段。
- 验收：正文、辅助信息字号符合规范；同一质控组件在各宿主中结构和间距一致；长规则号/哈希可换行且不挤压动作。

### F06 · P2 · 表格短标签被挤成两行

步骤 6 在 1280/1440 的“待处理”被分成“待处 / 理”，“机构规则”也换行；步骤 1 在 1280 的“未抽查”、签名状态同样拥挤。长规则编号可换行，但短状态不宜断成零碎字符。

- 建议：短标签 nowrap，并给状态列合理最小宽度；优先让长描述/规则编号换行，必要时收拢行内次要操作，而非压缩字体。
- 验收：三档桌面短状态完整一行；表格没有页面级横向溢出；操作列和长文案不相互覆盖。

### F07 · P2 · 版本页“查看”按钮掉入下一行首列

步骤 7 的“证据链”在行尾，而“查看”落到下一行最左侧。1280 和 1920 均测得“查看”仅 **22×32 px**；1920 的“证据链” x=1448、y=361，而“查看” x=263、y=401，属于结构错位，不是空间不够时合理的操作组换行。

- 根因依据：`web/src/vue/views/RecordVersionsPage.vue:200` 输出 7 个直接子元素；`web/src/vue/vue-shell.css:95` 只定义 6 列，第 7 个链接进入下一行的节点列。
- 建议：将证据链及查看/比较包进同一操作组，或明确第 7 列；不要改所有 `.version-row` 的通用样式而不回归其他使用者。
- 验收：查看/比较与证据链始终同属行尾操作组；最小控件宽高符合项目规范；单版本、多版本状态均检查。

## 不影响既有功能的整改边界

建议先修 F01、F02，再修 F04/F07，最后调整 F03 与统一 token。这里是整改建议，**尚未实施**。

- 仅变更目标组件布局、局部样式和展示文案；不改 API、查询键、保存/自动保存、防抖、版本哈希、签署门禁或质控规则。
- 共享对话框和样式变更必须回归原保存、签署、取消、Esc/焦点回归；不要全局压缩字号、强制隐藏溢出或调高 z-index 来掩盖问题。
- 后续修复验收应增加：干净/未保存/加载中/错误/自动质控运行/多条历史/长字段/空结果、三桌面宽度以及 200% 缩放。移动端不纳入本次范围。
