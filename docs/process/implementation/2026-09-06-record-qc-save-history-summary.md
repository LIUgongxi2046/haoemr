# 嵌入式病历质控 B2-SAFE：保存触发、运行历史与就诊汇总

日期：2026-09-06。状态：增量已实现，局部验证通过；全量发布门禁未通过。**不是原规划 19 项全部完成，不是生产就绪。**

## 实现范围

- 门诊、通用、住院编辑器提供本页有效、默认关闭的「保存后自动运行规则检查」。仅成功保存当前 DRAFT 版本触发，750ms 去抖，不延长正文保存事务，不调用外部模型，不自动改写正文。开启开关、加载页面和普通刷新不触发写入。
- 输入期间提供本地相同章节内容提示：只比较实际渲染的字段，限制长度，去重，不产生正式发现、扣分或签署阻断。
- 新运行记录保存 `trigger_stage` 和不可变 `finding_snapshots`；治理读取返回当前文书版本最近 20 次历史。旧运行字段保留空值，明确标记历史明细未知，不能用今天的 finding 重建过去。
- 新增受上下文授权的 `GET /encounters/{encounter_id}/record-quality`；只汇总本次就诊当前有效文书，排除 VOID，最多显示 100 份并返回总数和截断标志。按当前版本、内容哈希、来源水位显示未检查、失效、通过、警告、阻断；不返回病历正文，不宣称整次就诊放行。
- 就诊汇总折叠嵌入上述编辑器和病历工作台行内预览，没有新菜单；预览仍只读，不显示自动运行开关。
- 修复工作台计数混入历史版本未关闭发现的问题；当前版本计数包括 OPEN/ACKNOWLEDGED。
- 同一次保存的 POST_SAVE 重试在版本锁内按版本、哈希、规则集和来源水位去重，不重复追加运行及 Outbox。三段相同内容导致同一目标重复发现的计数也已去重，未降低规则严重度。

## 不影响原有业务的保护

1. 自动检查与正文保存解耦。检查失败明确显示「正文已保存，但自动质控失败」，不显示旧通过结论。
2. 患者、就诊、机构、院区、用户、角色、文书版本或授权变化时丢弃过期响应。只有已有保存队列、业务目标和权限身份完全相同的租约续期才重新绑定最新租约；不沿用旧凭证。
3. 通用及住院编辑器的后台数据刷新不覆盖未保存正文，保存仍提交开始编辑时的版本，避免后台更新悄悄绕过并发冲突。
4. 住院原有审签状态与内嵌面板使用同一加载、修改和错误边界；服务端签署规则及四角色链不变。
5. 回归暴露版本证据页的批量验签按钮在数据未加载时可点击并静默返回，已补充禁用条件；没有修改验签服务或放宽权限。
