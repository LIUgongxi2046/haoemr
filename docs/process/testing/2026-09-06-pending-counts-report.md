# 主菜单与业务页面待办统计修复

> 后续界面调整：用户要求取消逐页新增的待办清单。当前版本已删除正文顶部的待办汇总、明细和重复入口；统一入口改为 EVA 右侧的待办图标按钮，点击后才展开。下文原展示方式为早期验证记录，以本说明为准。

## 顶部统一入口调整

- 主菜单数量提示继续使用真实业务数据；各页面不再注入待办功能清单。
- 移除诊疗执行页新增的全中心待办指标，只保留当前执行队列的业务指标。
- 顶部面板仅列有待办或取数异常的业务，隐藏零待办的空队列；支持刷新、进入原处理页面、关闭按钮、Esc 和点击外部关闭。
- 待办按钮使用与顶部现有按钮一致的线性 SVG 图标，顺序为 EVA → 待办 → 操作指引。
- 实际组件渲染回归覆盖默认收起、页面清单不存在、按钮顺序、图标存在、零项隐藏及接口错误不假报空队列。
- 本轮 31 项定向组件/统计回归通过，Vite 生产构建通过。本地前后端服务均未在原端口运行，实页复测未完成。完整 vue-tsc 检查持续无输出，已终止本次启动的检查进程以释放资源，不将该检查记为通过。

## 原因与处理

原主菜单只保留了导航文字，已移除的原型数字没有接入真实数据。此次复用现有鉴权 API，恢复 14 个业务主菜单的统计；模拟接口没有独立业务待办队列，不编造数字。

- 门诊、急诊及任务中心沿用当前工作域选中的就诊；任务中心的「我的待处理」更正为「当前就诊待处理」，没有把当前就诊队列冒充全院个人工作清单。
- 住院角标读取授权病区全部在院患者的待完成文书。临床门户按选中就诊去重汇总临床任务，避免同次就诊在不同工作域重复累计。
- 病历、质量、资产、诊疗执行、数据、AI、知识、配置及管理分别读取各自业务队列。菜单明细列出统计范围及处理入口。
- 诊疗执行中心汇总专业队列的待办项次；同一临床事项在不同专业中可能有不同处理步骤，不作为唯一患者或唯一任务数。执行页面分别显示待办项次、当前队列任务数和待处理患者数。
- 数据中心的质量待办包含尚未关闭的问题，失败时不再显示「暂无开放阻断与待办，运行正常」。质量中心重试会重新获取明细，已归档质控对象不计入待办。
- 质量、数据及执行页面的「查看全部待办」改为进入对应业务队列，不再误导用户进入不涵盖这些业务的临床任务中心。
- 菜单区分真实 0、加载中和失败。已核实的列表返回上限触发时不使用截断队列计算完整总数。
- 统计缓存按账户、租户、院区、岗位、患者和就诊隔离；上下文切换时重置旧页面查询。成功业务写入触发刷新，租约签发不触发循环；可见页面每分钟复核并支持手动刷新。后台读取最多并发 4 个统计源。
- 覆盖展开、折叠及窄屏导航。旧原型 CSS 会在窄屏隐藏图标之外的 span，已覆盖该规则保证数量可见。
