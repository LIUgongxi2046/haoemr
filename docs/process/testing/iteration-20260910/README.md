## 发现的问题与处理依据

1. 原演示导入器用裸 MD5 转 UUID，部分字典和审计 ID 不满足前端契约。修正未来合成记录的 UUID 版本/变体位，保留旧测试数据库，不放宽契约、不重写旧审计。见 fixture-defect.md 和 05-fixture-identity-test.log。
2. 原模板审计 `now()` 在批量外层事务内相同，已观察到前驱分叉。仅将模板/安装审计改为实际时钟；同时将安装完成和回滚时间改为实际时钟。添加事件前驱和完成时间断言，未修写历史记录。见 10-audit-order-before.json、10/18 日志。
3. 其它院区同编码模板的内容不应出现在差异预览，现先核对范围再读取内容；医院新版本仍能查看上次包原文，但不会冒充未经修改的原包版本。
4. 既有模板预览曾硬编码医院及患者名字，现显示版式占位说明，布局不变，不让新装界面出现虚构患者。
5. 两次测试夹具/观察方式错误分别保留在 06-install-boundaries.log 和 13-performance-smoke.log。前者使用了非法模板 schema，后者误把重复请求返回 RUNNING 当作终态；修正夹具/观察方式后通过，业务门禁和最终结果断言未放宽。
6. 基线 `data-center-secondary-pages.test.ts` 的“人工确认门禁”文案断言仍失败，未删除或降低断言，不属于本批导入功能修复范围。
