# HaoEMR 开发方向纠偏与 UI 接线冲刺计划

> 日期：2026-08-22
> 性质：对「先完成全局、再动专科」执行期的一次**根因复盘 + 计划纠偏**
> 关联：`docs/process/planning/2026-08-14-haoemr-v1.0-implementation-backlog.md`（权威 backlog）、`docs/process/planning/2026-08-22-handover.md`

---

## 1. 根因（务必读透，别再犯）

**不是技术栈/脚手架问题。** Vue3 + Vite + Router + Pinia + TanStack Query + 自动生成契约 + 194 路由注册表**早已就位**。

真正的根因是：**「完成」的定义和「进度」的度量都被设成了后端指标，导致所有 agent 把 token 花在"看不见的地基"上，把"看得见的菜单"系统性后置。**

三个机制性错误：

1. **DoD 写反了**：backlog 写「不把 PRD/原型/静态 UI 计为已实现」。副作用 = UI 成了"不计分"的活，agent 永远不做 UI。
2. **度量是纯后端的**：机器契约记 `schemas/outputs/docs/process/operations/tests`，从无「可用菜单数」。测什么就优化什么。
3. **纵向切片被做成横向层**：真纵向 = UI→API→DB 端到端；实际 = 一张表+服务+API+测试（后端横切一层），UI 层始终缺。

**Agent 盲区**：agent 按「verify.sh 全绿 = 完成」汇报，而 verify 是后端/测试门禁，不测"人能不能点"。Agent 没有"这不能用"的人类直觉。

## 2. 结论：继续，不推翻重来

后端（132 迁移 + 477 测试）是真实资产，推翻 = 把做对的也丢掉。缺的只是 UI 层，是**加法**。

## 3. 纠偏：换三样东西

| 原来（错） | 改成（对） |
|---|---|
| 度量 schemas/docs/process/operations/tests | **主度量 = 可用菜单数 / 194** |
| DoD = 后端切片 + 测试绿 | **DoD = 菜单在 UI 可点、连真 API、状态齐全** |
| 任务 = 一个领域一张表 | **任务 = 一个菜单端到端（UI→API→DB）** |

### 统一"菜单切片"交付模板（替代原后端切片模板）
每个菜单一个任务，完成后必须：
1. `web/src/vue/views/<Xxx>.vue` 页面，**视觉对齐原型**（参考 `prototype/app/`、`docs/design/ui-delivery/tokens.json`）。
2. `router.ts` 的 `nativeComponents` + `route-registry.ts` 的 `nativeVueRouteIds` 双登记。
3. 复用 `web/src/clinical-api.ts` 既有 API 函数（有则复用，无则新增，**禁止再新建后端表/服务，除非该菜单真的没有后端**）。
4. 覆盖状态：loading / empty / error / permission / success / conflict（用 `ClinicalPageState.vue` + `toClinicalIssue`）。
5. 验收：`cd web && npm run build`（vue-tsc 通过）+ 浏览器打开 `#/<route_id>` 真实可点。
6. 回写：README 第 5 行把「可用菜单数 / 194」更新为**主指标**。
