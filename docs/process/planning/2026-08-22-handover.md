## 0. 最重要的三句话（先读这个）

1. **方向已纠偏**：此前「后端优先、UI 后置」是错的。现在 **"完成" = 菜单在 UI 可点**，主度量 = **可用菜单数 / 194**，不再用 schemas/tests 当进度。
2. **不推翻重来**：后端 132 迁移 + 477 测试是真实资产；缺的是 UI 层，是**加法**。但 **UI 优先，后端复用，禁止再堆后端切片**。
3. **架构不用大动**：模块化单体 + PostgreSQL + 显式 SQL(JdbcClient) + Vue 单栈 + 契约优先 = 合理甚至优秀。**禁止换 MyBatis-Plus/JPA、禁止换 MySQL、禁止微服务化、禁止追 Spring Boot 新大版。**

## 4. 既定工程纪律（每片务必照做）

> 完整 19 条原则见 `DEVELOPMENT_PRINCIPLES.md`；这里只留"怎么做对"的操作细则。

**后端切片（仅在确实需要新后端时）** = 迁移 + 模块 + 契约 + 测试 + 全量 verify + 报告 + 台账回写：
1. **迁移**：`V<n>__<name>.sql` + `assert-v<n>.sql`；约束**显式命名**；**绝不可改已应用迁移**（checksum），修复只能新迁移。
2. **接线 test-schema.sh**：`migration_v<n>` + `assertions_v<n>` 变量 + required-file 循环项 + psql 链尾行（`-c 'rollback'`），四处都改。
3. **契约**：先改 `contracts/openapi.json`（`additionalProperties:false`、snake_case），再 `npm --prefix contracts run generate`。**新表名/`$ref`/`operationId`/路由路径必须先 `grep` 全仓查重**。
4. **模块**：`Service/Controller/Exception/ExceptionHandler` + 1 测试；写操作统一 `beginCommand`(幂等) + `appendEvidence`(审计链+outbox) + `completeCommand`；乐观锁 `expected_row_version` + `for update`。
5. **测试**：`@SpringBootTest(RANDOM_PORT) @ActiveProfiles("dev-synthetic")`；种子 `TENANT/ORGANIZATION/FACILITY/USER/ROLE`（`018f0000-...aa01..aa05`）；**无 `@Transactional`，数据跨 run 持久化** → UUID 派生唯一键、计数用差值断言；可空列用 `cast(:x as uuid/timestamptz)` + 传 `UUID/OffsetDateTime`（pgjdbc 不认 `Instant`）。
6. **验证**：后台 `scripts/verify.sh > /tmp/verify-v<n>.log 2>&1; echo "VERIFY_EXIT=$?"`，`job_output wait:true`（勿 `| tail` 吞退出码）。

**菜单切片（当前主流，优先做这个）** = 见 `docs/process/planning/2026-08-22-ui-replan.md` §3 模板：Vue 页面视觉对齐原型 → `router.ts` + `route-registry.ts` 双登记 → 复用 `clinical-api.ts` 既有 API → 覆盖 loading/empty/error/权限/success → `npm run build` 通过 → 更新"可用菜单数/194"主指标。

## 7. 架构决策结论（本轮复盘定案，别再摇摆）
- **继续，不推翻重来**。后端是资产，UI 是加法。
- **保留 JdbcClient**，禁止换 MyBatis-Plus/JPA/Hibernate（会重写 102 个 Service + 丢 DB 约束优势）。
- **保留 PostgreSQL**（医疗严谨性 + 信创国产库 PG 兼容），不换 MySQL/Oracle。
- **Spring Boot 4.1.0 可选降 3.5.x**（求稳/招人/集成；非必须，代码已在 4.1 全绿）。
- **面向中国信创**：目标库金仓/openGauss/GaussDB/达梦 PG 兼容模式；可引入 Element Plus/Knife4j（纯加法）。
- 详见 `DEVELOPMENT_PRINCIPLES.md` §二/§三。

## 8. 踩坑记录（后续开发必读）
1. **表名/契约名冲突**：V131 最初叫 `patient_match_candidate` 与 V29 MPI 的 `patient_match_candidate` 重名 → 字段字典重复 + Spring 路由歧义。**新表名/`$ref`/`operationId` 先 `grep` 查重。**
2. **pgjdbc 不认 `Instant`**：可空 timestamptz 用 `cast(? as timestamptz)` + 传 `OffsetDateTime`。
3. **可空列类型推断**：`values(..., ?, ?)` 两个 `null` 报「could not determine data type」，用 `cast(:x as uuid/timestamptz)` 显式定型。
4. **测试数据跨 run 持久化**：计数/去重断言用差值或 UUID 派生唯一键。
5. **`OutboxDispatcherTest` 并发抖动**：outbox 积压 > 领取批量导致事件不被优先领取；把用例事件 `available_at` 置最旧。
6. **`Instant.now().atOffset(ZoneOffset.UTC)`**：timestamptz 统一走 `OffsetDateTime`。
7. **字段字典唯一键**：`generate.mjs` 用 `entity.field` 做唯一键，同名表会静默重复。
