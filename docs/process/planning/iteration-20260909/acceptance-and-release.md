# 验收与发布执行手册

2026-09-09 · 所有标准为未来验收要求。本轮仅核对文档结构和源码依据，未运行以下业务测试或操作。

## 统一完成定义

任务状态：PLANNED → IN_PROGRESS → READY_FOR_REVIEW → VERIFIED。验收结果单独使用 NOT_RUN / PASS / FAIL / BLOCKED / STALE / N_A。N_A 必须说明原因和确认人，不计入有效执行分母；历史结果对新候选默认失效，必要时依据影响评估重跑。

一个业务切片只有同时满足以下条件才完成：

1. 任务要求的入口在**原系统真实登录应用**可达；接真实 API，主流程和适用的 loading/empty/error/permission/success 状态齐全。
2. UI 结果与 API、机构/用户上下文、数据库效果及审计相互对应；仅有服务端测试或模拟原型不算完成。
3. 写操作具备既有幂等、授权、审计/Outbox；关键状态/范围/不可变规则由数据库兜底。未新增无必要的表、服务、路由或审批链。
4. 任务级 ITER-TAC 全部满足；关联原 ITER-AC 由其全部覆盖任务共同证明，不能一张任务卡通过就宣称该 FR 完成。
5. 接口变更先改 OpenAPI，再生成 Java/TS；当前消费者兼容，新增迁移不修改已应用历史校验和。未改接口/Schema 时明确“不适用”并给差异证据。
6. 相关回归通过；阻断缺陷为零。未解决非阻断项逐项说明影响、责任和是否阻止所选范围交付，不能笼统“已知问题不影响”。
7. 数据保护及回滚方案实际可执行。涉及数据的任务不能只写“git revert”，也不能删除审计/已签署版本代替修复。
8. 变更清单、测试证据、配置与恢复说明完整；不覆盖已有用户改动。

工程决策任务的完成是“输入有证据、复用/兼容/安全边界明确、下游可开工”，不是编造 UI 通过。007 的夹具与格式完成不等于 G-PACK 已满足；030 的用例契约完成不等于真实模型发布获准。

## 缺陷分级与证据记录

- P0：跨机构/患者错误、数据丢失、越权审批/签署、秘密暴露、不可控重复业务效果。停止候选交付并保留证据。
- P1：主流程不可完成、回滚/恢复不可核对、医院版本被覆盖、原菜单或关键功能退化。对应里程碑不通过。
- P2：不阻断任务但影响可用性或可理解性的问题；记录影响和负责人，所选范围是否放行需具体判断。

每次执行在 acceptance-matrix.csv 填 candidate_sha、environment、evidence_path、actual_result、executor、executed_at 和 status。报告需附工具/命令、实际响应/日志、数据核对及必要截图，证据去敏。写入失败必须能对应失败编号与原操作；提交后响应丢失的“未知”单独记录，不默认失败或成功。

计划通过率是 **已满足标准/适用标准**，同时列 NOT_RUN/BLOCKED/STALE 数量；禁止通过排除未执行项制造 100%。本轮所有 129 项为 NOT_RUN。
