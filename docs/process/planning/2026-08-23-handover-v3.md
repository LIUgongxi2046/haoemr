## 5. 剩余工作（按优先级）

### 5.1 【紧急·已定位根因】指标快照列表 `CONTRACT_MISMATCH`

- **症状**：`data-center` 等 5 个指标页点进去显示「加载失败：CONTRACT_MISMATCH 服务响应与临床契约不一致」。服务端一切正常（`POST /metric-snapshots/compute` 返回 200，`GET /metric-snapshots?metric_type=DATA_CENTER` 返回 200 且 DB 有 9 条快照）。
- **根因**（已用 Playwright 抓到原始响应确认）：后端 `MetricSnapshotWire` 返回 `"period": null`（compute 从不写 period）、`"unit"` 也可能为 `null`；而 `contracts/openapi.json` 里 `MetricSnapshotWire.unit`/`period` 声明为 `"type": "string"`（不可空），生成 `z.string().optional()`。**`.optional()` 只接受 `undefined`，不接受 `null`**，strict 模式下直接抛 `CONTRACT_MISMATCH`。项目里可空字段的既有约定是 `"type": ["string","null"]` → 生成 `.nullable().optional()`（见 `AuditEvent.actor_user_id`），而本处漏写了 null 类型。
- **修复（二选一，推荐 1）**：
  1. 契约优先改 `contracts/openapi.json` 的 `MetricSnapshotWire` 与 `MetricSnapshotRecordRequest` 两处 `unit`/`period` 为 `"type": ["string","null"]` → `npm --prefix contracts run generate` → 重建 web。
  2. 后端对 Wire record 加 `@JsonInclude(JsonInclude.Include.NON_NULL)` 不输出 null。
- 修复后验证：`data-center` 表应展示 患者数/就诊数/文书数/医嘱数 四行。
