# HaoEMR 交接文档 v2（2026-08-23 全量开发完成后）

> 读者：接续开发 agent。开工先读 `DEVELOPMENT_PRINCIPLES.md` + `docs/process/planning/2026-08-23-handover.md`（v1）+ 本文档。
> 本文档回答一个核心问题：**前后端/数据库/Agent 四层分别开发到什么程度，还差什么。**

## 0. 总览

- **菜单主度量：194/194 可用，0 个 `NOT_AVAILABLE`**（本冲刺从 150 → 194）。
- 技术栈不变：Vue 3 单栈前端 + Spring Boot 模块化单体后端（JdbcClient + 显式 SQL）+ PostgreSQL 单一事实源 + Flyway V1–V162。
- 验证全绿：`npm run build`=0、`vue-tsc`=0、`vitest`=17/17、浏览器路由审计 194/194、契约 check 443 schemas 无漂移、red-team/route-map/security-scan 全 PASS。

**关键诚实结论**：菜单层 100% 打通，但**功能层不是 100%**。194 个路由里约 42 个是「演示/占位」形态（模拟适配器 13 + 可视化配置草稿 13 + 模拟看板 14 + 模拟接口控制台等），它们**没有真实后端业务语义**。真正的功能完整性仍需三类后端支撑：真实适配器、配置持久化引擎、指标语义层。

- 真实病理/麻醉/治疗专科系统（`pathology-workbench`/`anesthesia-workbench`/`therapy-workbench`，X01/H01 未实现）

**B. 配置持久化引擎（13 个可视化配置路由的真实版，G01 重设计）**

**D. 生产真实依赖（prod profile 启动门禁明确 NO-GO）**
