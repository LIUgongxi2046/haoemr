# v0.2 修订：完全融入现有 HaoEMR

日期：2026-09-09。状态：CREATED，待评审。用户本轮明确约束高于 v0.1 的推导建议；以下内容已同步到主需求、页面映射与原型。

## 结论

**不改变原架构，不改变原设计风格，不新增主菜单，不另建系统。** 本轮管理功能全部有现有宿主入口，因此无需启用“无法容纳时才考虑一个新主菜单”的备用方案。系统管理的现有二级导航也保持不变，新增交互优先用已有页面中的区块、页内标签和 AdminActionDialog。

## 重新核对的项目事实

| 现有资产 | 核对结果 | 对新需求的约束 |
|---|---|---|
| `ClinicalShell.vue` | 15 个一级菜单；系统管理已有 13 个二级链接，其中品牌与名称是参数页查询视图；另有业务配置/集成跳转 | 保留菜单名称、顺序、分组和域边界；16 个 SCR 编号不是 16 个菜单 |
| `AdminWorkspacePage.vue` | 已有管理指标、模块入口、高优先级待办、发布/回退摘要 | 初始化采用这里的一段检查清单，不另建欢迎首页或交付控制台 |
| `OrganizationAdministrationPage.vue` | 组织树、有效期、院区/科室/病区/床位、创建及组织导入均已实现 | 复用原表单和领域用例，仅识别初始化缺项；不再设计平行机构注册 |
| `AdminParametersPage.vue` | 参数页复用 ConfigurationStudioPage，品牌使用 `view=branding` | 在参数页内加“模块初始化”标签，不改变原参数类型或原品牌入口 |
| `AdminJobsPage.vue` | 已有任务定义、运行记录、逐项发现、重试与取消 | 安装记录呈现在该页新增的页内“配置安装记录”视图；不得把原任务“部分成功”规则套给原子安装 |

`view=initialization`、`view=installations`、`source_install=…` 仅为建议的页内状态表达，当前并非已实现查询参数；实际契约由现有路由和页面状态机制承接。新增根路由数目标为 0，主菜单增量为 0，二级导航增量为 0。

## 架构与服务复用

保留 Spring Boot 模块化单体、PostgreSQL、JdbcClient/显式 SQL、Flyway、Vue 3 单入口/单路由注册、OpenAPI 契约生成、上下文授权、数据库强约束、幂等与审计/Outbox。禁止为本期更换框架、数据库、ORM、拆微服务、平行前端应用或新增独立认证。

- 机构创建复用 OrganizationAdministrationService；人员与身份复用 WorkforceAdministrationService 和既有认证授权。
- 内容导入使用现有领域写用例；模板用 DocumentTemplateService；配置版本用 ConfigurationService/ConfigurationRuntimeService；能力包用 platform 下已有 CapabilityPackService 与 CapabilityPackReleaseService。
- 安装本身需要补充“清单预检、安装来源、操作恢复”的缺失能力，但不能把现有包定义/任务 API 冒充安装器。是否需要最小新表由数据盘点决定，不能以“不改架构”为由删除必要记录，也不预先复制领域表。
- 任务页只是安装运行记录的展示宿主；安装原子性、结果未知、失败回滚和禁止中途取消独立于既有通用任务状态。
- 审批使用目标领域的实际状态机。模板首包不从新流程定义 `PENDING_APPROVAL`；能力包仍保留其自己的灰度状态机，不合并。

## 新的验收要求

1. 对照 ClinicalShell：主导航 15 项与现有值逐项一致；系统管理 13 个二级链接逐项一致；无新主菜单。
2. 对照样式来源：原型引用现有四份 CSS，顺序相同；新增样式只作用于增量区块/评审工具，不覆盖 `.shell/.sidebar/.main/.btn/.card/:root`。
3. 原型默认落在既有系统管理工作台，安装在现有页面内完成；16 屏地图移入文档，不再作为左侧导航。
4. 组织树、参数管理、任务记录、模板发布、审计、能力包边界保持；临床与 Eva 仅回到原入口，不复制完整临床页面。
5. 旧 v0.1 的浏览器测试仅为历史；修订原型重新检查主菜单一致性、安装→任务→模板的关联和桌面/手机布局。
