# HaoEMR 医疗 UI 设计系统基础契约

> 状态：`CREATED`。本文件只定义不依赖 A/B/C 品牌选择的医疗安全、布局、组件和可访问性规则；最终颜色值、材质和图标资产在视觉方向确认后写入 `design-system.md` 与 `tokens.json`。

## 1. 设计目标

1. 在诊所、基层、二级和三级医院使用同一套 UI 语义与组件，不按医院等级复制产品。
2. 让患者、就诊、任务、风险和业务状态始终比装饰元素更醒目。
3. 支持高密度临床工作站、标准密度管理后台和触控密度床旁 PWA。
4. 病历正文、来源、质控、签署和版本使用清晰分层，避免在一个固定三栏中相互挤压。
5. AI 是有来源、可拒绝、可停用的协作者，不伪装成临床事实或系统硬规则。

## 2. 信息层级

### L0 全局壳层

- 固定显示机构/院区、岗位/班次、当前用户、全局搜索和 AI医助小南入口。
- 一级导航只允许一个活动项；未知或无权限深链进入安全页，不保留旧患者上下文。

### L1 工作域

- 门诊、急诊、住院、核心专科、病历、质量、病案、协同、数据、AI、业务配置和系统管理分别使用稳定入口。
- 工作域之间只能通过标明目标域的跨域按钮跳转。

### L2 患者与任务上下文

- 患者级页面持续显示：姓名、性别、年龄/出生日期、患者号、就诊号/住院号、科室/病区/床位、责任人、严重过敏、病危/隔离等。
- 切换患者、就诊或岗位前检查草稿、录音、审批和未完成高风险动作。

### L3 任务内容

- 工作台：队列、风险、时限、下一动作。
- 病历/表单：正文、结构化字段、来源、保存与签署。
- 执行工作台：业务状态机、核对、执行、结果与恢复。
- 管理页面：目录、详情、差异、验证、审批、发布和审计。

### L4 反馈与阻断

- 硬阻断：页面内持久显示，提供原因、对象、来源、解除条件和责任人，不使用可自动消失 Toast。
- 警告：允许继续时必须说明风险和记录理由。
- AI 建议：显示模型/Agent/Skill 版本、来源、置信/失效条件和“待确认”状态。

## 3. 密度模式

| 模式 | 适用 | 基础行高 | 控件高度 | 页面内边距 | 最小触控 |
|---|---|---:|---:|---:|---:|
| Compact | 门急住、病历、医技、专科工作站 | 32px | 28–32px | 12–16px | 鼠标键盘为主 |
| Standard | 质量、数据、配置、系统管理 | 40px | 36px | 16–24px | 36px |
| Touch | 床旁、移动查房、扫码/给药 | 48px | 44–48px | 16px | 44×44px |

密度变化只改变空间与控件尺寸，不改变字段、状态、权限或风险语义。

## 4. 栅格与断点

- 间距使用 4px 原子、8px 主栅格。
- `compact`：1024–1279；`medium`：1280–1599；`wide`：1600–1919；`ultra`：≥1920。
- 主侧栏 216–248px；患者条可换行但风险标签和切换动作不离屏。
- 病历专注编辑最大正文宽度 920px；来源/质控使用可收起抽屉或独立页面，不永久压缩正文。
- 200% 缩放时允许布局降为单列，不允许主要签署/保存/返回操作被遮挡。

## 5. 医疗语义体系

| 语义 | 视觉编码 | 使用范围 | 禁止 |
|---|---|---|---|
| Critical/Blocked | 红色 + 八边形/停止图标 + “阻断”文字 + 左实线 | 错患者、错侧别、严重过敏、剂量越界、签署阻断 | 用于品牌或普通强调 |
| Warning | 琥珀 + 三角图标 + 明确后果 | 临期、需复核、允许说明理由继续 | 与硬阻断混用 |
| Success | 青绿 + 勾选 + 完成对象/时间 | 核验通过、业务完成、恢复成功 | 仅表示“消息发送成功”而非业务成功 |
| Information | 蓝色 + 圆形信息图标 | 来源、说明、普通任务 | 伪装成风险 |
| AI Draft | 紫色 + 星形/AI 标签 + “待确认” | AI 摘要、草稿、建议、候选动作 | 与人工事实使用同一外观 |
| Stale/Offline | 中性灰 + 断链/时钟 + 数据时间 | 缓存、过期、断网、接口降级 | 静默展示旧数据 |

## 6. 组件契约

### 患者身份条

- 必须包含患者双标识、当前就诊、责任范围和风险标签。
- 姓名相同或患者切换时显示二次核验；打印/截图模式使用受控脱敏。

### 按钮

- 层级：主操作、次操作、文本操作、危险操作。
- 状态：default、hover、focus-visible、pressed、disabled、loading、success、error。
- 同一页面最多一个主操作；危险操作不与主操作同色。

### 表单与病历编辑器

- 标签不依赖 placeholder；必填、来源、单位、时间和版本可见。
- 自动保存显示“保存中/已保存/失败/冲突”，不得只显示一个圆点。
- 已签内容只读；更正进入新版本并展示差异、理由和传播范围。

### 队列与表格

- 表头可固定；风险、时限和患者身份不可在横向滚动后丢失。
- 默认提供密度、列显隐、筛选和受控导出；空状态说明过滤条件与恢复动作。

### 弹窗/抽屉

- 普通确认使用对话框；复杂高风险动作使用独立审查页或宽抽屉。
- 高风险确认展示具体患者、对象、变化、后果、批准范围、恢复方式和审计。

### AI医助小南

- 顶栏和浮动入口在所有授权桌面页可达；不得遮挡固定操作。
- 面板顶部显示患者/就诊/任务上下文；无患者时显示安全空上下文。
- Tool 动作在原业务状态机内逐次批准，拒绝后不执行。

## 7. 状态覆盖

每个适用页面至少设计：初始、加载、空、部分数据、过期、慢网、离线、超时、重连、无权限、会话过期、进行中、成功、失败、撤销、确认、锁定、并发冲突和恢复。

专科额外覆盖：设备离线/重传、身份/侧别/部位/牙位冲突、剂量计算异常、特殊隐私、母婴/夫妇关系异常和专业硬阻断。

## 8. 可访问性

- 正文对比度目标 ≥4.5:1；大字和非文本控件 ≥3:1。
- `focus-visible` 不得删除；键盘顺序与视觉顺序一致。
- 状态不只依赖颜色，图标按钮有中文可访问名称。
- 支持减少动态效果；不使用连续闪烁和大范围视差。
- 病历长文、表格、图表在系统大字体和 200% 缩放下仍可完成核心任务。

## 9. 禁止项

- 不使用 Emoji 作为最终功能图标。
- 不使用大面积渐变、玻璃拟态或装饰插画覆盖临床信息。
- 不以隐藏按钮代替权限；不把 AI 建议、规则和临床事实画成同一状态。
- 不把红/绿作为唯一差异；不通过缩小到 10px 字体解决拥挤。
- 不按科室任意换品牌色，避免风险色和科室色冲突。
