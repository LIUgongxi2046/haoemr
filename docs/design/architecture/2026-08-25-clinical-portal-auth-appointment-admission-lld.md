# 系统统一登录与临床门户：预约挂号、办理入院详细设计

状态：IMPLEMENTED / ACCEPTED  
日期：2026-08-25  
范围：全系统统一登录与会话、临床业务门户头部身份、预约挂号、班次号源配置、床位配置、办理入院

## 1. 依据与业务边界

- 国家卫健委《住院病案首页数据质量管理与控制指标（2016版）》将首页数据分为患者基本信息、住院过程信息、诊疗信息和费用信息，要求完整、准确、规范。
- 国家卫健委《住院病案首页部分项目填写说明》包含医疗机构、医疗付费方式、健康卡号、住院次数、病案号、入院途径、入院科别/病房、门（急）诊诊断等项目。
- 《病历书写基本规范》要求入院记录另行记录姓名、性别、年龄、民族、婚姻、出生地、职业、入院日期、记录日期、病史陈述者，以及主诉、现病史、既往史、查体等医疗内容。
- 《医疗机构病历管理规定（2013年版）》要求为门（急）诊和住院患者建立病历并使用唯一标识管理。

因此本模块把“办理入院登记”和“医生书写入院记录”分开：前者完成身份核验、住院业务信息、床位占用和审计；后者继续由已有住院文书任务完成。登记页面不代替病历书写。

## 2. 会话与登录

登录是 HaoEMR 整个系统的公共安全边界，不属于临床业务门户子页。正式入口为 `/#/login`，使用 `SYSTEM_AUTH` 独立布局，不创建业务顶栏、侧边栏、子导航或 AI 工作上下文。未登录访问任何业务路由均转入该页，登录成功后安全返回原请求路由。`/#/login-context` 仅作为旧深链兼容别名。

### 2.1 数据模型

- `dev_user_credential`：仅 `dev-synthetic` 环境启用的用户名和 BCrypt 密码摘要，关联 `app_user`，记录失败次数、锁定时间和最近登录时间。
- `user_session`：保存不可逆的 SHA-256 令牌摘要、租户、用户、签发/到期/撤销时间、最近访问时间。数据库只保存摘要，不保存原始令牌。
- 生产环境继续使用 OIDC/JWT；本地真实登录接口只能在 `dev-synthetic` profile 注册，禁止生产回退到本地密码。

### 2.2 API

| API | 输入 | 输出 | 失败 |
|---|---|---|---|
| `POST /api/v1/session/login` | username, password | bearer_token, user/context, expires_at | 401 凭据错误；423 锁定 |
| `GET /api/v1/session/current` | Bearer token | 当前用户、机构、院区、角色、班次 | 401 会话无效/过期 |
| `POST /api/v1/session/logout` | Bearer token | 204 | 幂等撤销 |

登录成功、失败和退出均写审计事件。前端令牌只放 `sessionStorage`；退出后清空令牌和工作上下文。头部姓名和班次来自 `/session/current`，不再硬编码。

为保持已有自动化测试可运行，固定 `dev-synthetic-token` 仅作为测试兼容通道保留；浏览器应用不再默认使用它。

## 3. 预约挂号

### 3.1 页面流程

1. 输入身份证号、就诊卡号或姓名检索患者；全号仅在服务端做哈希等值匹配，响应只返回脱敏标识。
2. 选择医院/院区、科室、医生、日期和就诊类型。
3. 服务端返回该医生可预约且剩余号源大于零的班次。
4. 选择预约来源（患者预约或现场挂号）并提交。
5. 列表展示患者中英文姓名、性别/年龄、医院、科室、医生、时段和中文状态；取消、签到、叫号、接诊按状态开放。

### 3.2 数据与一致性

- `schedule_slot` 增加 `doctor_user_id`，号源唯一键覆盖院区、科室、医生、日期和起止时间。
- 预约读取时通过号源关联医院、科室、医生，避免冗余名称漂移。
- 预约时锁定号源行并原子增加 `booked_count`，已有幂等键、审计和 outbox 机制保持不变。
- 患者搜索增加身份证/就诊卡原文的 SHA-256 等值查询，不写日志、不回传原值。

### 3.3 页面归属

- “预约挂号”只保留患者检索、选科室/医生/时段、预约及就诊队列操作。
- “业务配置”增加“班次号源”区域，支持号源新增、查询、启停；临床门户不直接暴露号源配置表单。

## 4. 床位与办理入院

### 4.1 床位展示规则

- 床位数据库仍按病区保存原子床号，如 `01`、`02`；页面统一显示 `科室-床号床`，例如 `心血管内科-02床`。
- 床位看板响应增加医院、科室、病区名称和规范展示床号，避免前端使用固定文案拼接。
- 合成数据使用“江城大学附属医院本部 / 心血管内科 / 心血管内科一病区”，配置 01–12 床，其中 02 床为占用，其余可用。

### 4.2 入院登记字段

必填：患者、住院就诊、医院、入院科室/病区/床位、经治医生、入院时间、入院途径、入院类型、病情分级、入院诊断、付费方式、身份核验方式、联系人姓名/关系/电话。  
选填：入院证/医嘱编号、诊断编码、转入机构说明、备注。

服务端校验科室—病区—床位归属、医生有效性、患者/就诊一致性、电话和枚举值；事务内锁床、创建入院记录、占床、创建文书任务、写审计/outbox。任一步失败整笔回滚。

### 4.3 状态与错误恢复

- 页面状态：初始、患者检索中、患者已选、床位加载中、提交中、成功、可恢复失败。
- `BED_OCCUPIED`：刷新床位后重选；`PATIENT_CONTEXT_DENIED`：重新检索患者；`ADMISSION_VALIDATION_FAILED`：保留表单并定位字段；`IDEMPOTENCY_REPLAY`：刷新结果，不重复占床。

## 5. 验收契约

- 未登录访问任何业务页转入独立 `/#/login`，页面不显示任何业务门户壳；登录后全系统头部显示数据库中的用户姓名和班次；退出后令牌被数据库撤销。
- 预约页面没有号源维护表单；用身份证/姓名可检索患者，必须选择科室、医生、班次才可预约。
- 预约列表与候诊/就诊列表均显示患者、医院、科室和医生，操作按钮执行真实 API 后刷新数据库状态。
- 业务配置可以新增并查询医生号源。
- 床位统一显示“科室-床号床”，真实样例不少于 12 张。
- 办理入院完整字段写入 `inpatient_admission`，占床和文书任务同事务落库；重复提交不产生第二次占床。
