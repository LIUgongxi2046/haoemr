## 1. 执行摘要

- **问题**：临床知识内容（医保规则、术语、药品目录、疾病/手术编码、检验项目、知识图谱、临床路径、质控依据等）散落在规则引擎/文档/模板与外部知识源中，缺乏统一的知识库、可寻址引用、图谱关系与版本治理；各 Agent 无法以受控方式检索并引用这些知识。
- **目标用户/购买者**：知识库管理员、临床专家（审评人）、临床医生/药师/护士/质控/病案人员、AI 治理与安全审计、机构管理员。
- **价值主张**：把「散落的知识」收敛为「可编辑、可链接、可检索、可版本、可引用、可反馈」的院内知识资产，并让 Agent 以**最小权限 + 可寻址引用 + 版本锁定**的方式消费这些知识，而不是把知识全文塞进 Prompt。
- **本期目标**：建成知识中心五个能力域——①知识库管理 ②双向链接与图谱 ③混合检索 ④版本化治理 ⑤Agent 知识检索联动；首批从外部知识源**选择性抽取有用数据**（见 §4.1）。
- **非目标**：不做确定性规则引擎（用药安全、质控硬门、路径状态机不迁移）；不做通用笔记/个人日记/第三方插件市场；不引入独立搜索引擎/Neo4j/重型 RAG 框架；不做移动端独立 App（复用现有响应式）；**不修改外部知识源原始文件；不全量照搬外部源，不引入七巧板/HiTA 等第三方授权内容**。
- **成功指标及口径**（`待基线化` 项先标测量计划，不伪设阈值）：
  1. 知识可寻址引用率 = 检索命中且能回表定位到 `(doc, version, chunk/字段)` 的引用数 / 总引用数，目标 100%。
  2. 越权引用数（跨租户/跨用途/跨敏感级命中）= 0。
  3. 未评审/过期知识作为「强提示」命中数 = 0。
  4. Agent 人工复核采纳后的修改率、路由改选率、重复/冲突率——`待基线化`，由 S009 用标注基线得出。
  5. 知识反馈闭环时长（命中→反馈→评审→版本更新）——`待基线化`。

## 3. 用户、角色与权限

| 角色 | 使用情境 | 目标 | 数据范围 | 关键权限 |
|---|---|---|---|---|
| 知识库管理员 `KNOWLEDGE_ADMIN` | 维护知识资产 | 登记来源、导入、编目、元数据、发布草稿 | 全库（按敏感级） | 来源登记、导入、分块、元数据、发起发布 |
| 临床专家/审评人 `KNOWLEDGE_REVIEWER` | 审评知识 | 校验来源、适用性、有效期、冲突 | 被指派的待评审知识 | 评审、批准、驳回、退役（职责分离：不能自编自批） |
| 临床使用者（医生/药师/护士/质控/病案） | 检索与消费 | 在工作流中检索并引用知识 | 按角色+用途+敏感级 | 检索、查看、命中反馈 |
| AI 治理/安全审计 `SECURITY_AUDITOR` | 审计 | 追踪命中、越权、版本、反馈 | 审计视图 | 只读审计、越权告警 |
| 机构管理员 `ADMINISTRATOR` | 治理开关 | 机构级启停、敏感级策略 | 机构策略 | 启停、敏感级策略、紧急停用 |

权限统一用「主体—资源—动作—范围—条件」表达。示例：
- `KNOWLEDGE_ADMIN` 对 `knowledge_document` 执行 `IMPORT/EDIT/METADATA/SUBMIT_RELEASE`，范围=本租户，条件=非 RESTRICTED 或已二次授权。
- `临床使用者` 对 `knowledge_chunk` 执行 `READ/RETRIEVE`，范围=角色用途白名单 ∩ 敏感级 ∩ 授权水位，条件=版本为 `APPROVED/ACTIVE` 且未过期。
- 编辑、评审、发布、机构启用四类动作**职责分离**（延续 FR-056）。

## 4. 范围

### 4.1 范围内

1. 知识中心入口（平台中心第三个菜单）与总览工作台。
2. 知识条目编辑：Markdown + 双向链接 `[[]]` + 结构化元数据（分类分级/有效期/许可/来源权威）。
3. 双向链接、反链（backlinks）与图谱可视化/遍历（depth≤2）。
4. 混合检索：全文（PostgreSQL FTS）+ 语义（pgvector）+ 图（depth≤2）+ 精确/术语，RRF 融合、重排、可寻址引用。
5. 知识模板：指南/药品说明书/临床路径/质控依据/通用。
6. 版本化治理：来源登记（SRC-KNOWLEDGE）→ 导入 → 分块 → 评审 → 发布 → 回退/退役。
7. 术语/本体：引用现有主数据字典做概念归一与映射。
8. 知识命中/反馈闭环：命中、采纳、驳回、纠错 → 驱动版本更新。
9. Agent 知识检索联动：`knowledge_search` / `knowledge_lookup` / `knowledge_graph` 三个受控 Tool + 知识版本锁定进 RunScope。
10. 首批内容域（来自只读外部知识源 E-009，**选择性抽取有用数据**）：知识图谱（疾病/症状/药品/检验检查/临床路径/医保目录/科室机构/系统字典/编号表/问诊题库）+ 知识详情（医保用药规则、医保诊疗项目规则、质控规则、药品目录、诊疗项目/价格、疾病/诊断编码、手术编码、检验项目、医用耗材）。明确**排除**七巧板医学术语集、HiTA 资源等第三方授权内容。
11. 外部知识源只读接入：选择性读取本地 Obsidian 库有用数据、导入本库副本、禁止写回源库（KC-FR-013）。

### 4.2 范围外

- 确定性规则引擎与状态机（用药安全、质控硬门、路径状态机、数据质量规则）——不迁移、不复制。
- AI 资产目录（模型/Prompt/Agent/Skill/Tool）——保留在 AI 中心，知识中心只提供被引用关系。
- 主数据字典/术语管理本体——保留在系统管理，知识中心引用。
- 通用笔记/日记、第三方插件市场、Canvas 无限画布、本地文件同步、独立移动端 App。
- 独立搜索引擎集群（OpenSearch）、图数据库（Neo4j）、重型 RAG 框架（LangChain/LlamaIndex）。
- 对外部知识源原始文件的任何写入/修改/删除。
- 第三方授权资源（七巧板医学术语集、HiTA 资源）与非临床有用内容——**不导入**。

### 4.3 依赖与约束

- 依赖既有主数据字典（术语归一）、Agent Harness Tool Gateway（联动）、PostgreSQL + pgvector（检索）、对象存储（可选原文）。
- 约束：知识文档按不可信内容处理，不能贡献 System/Developer 指令；`RESTRICTED` 敏感级知识需数据层硬门；删除传播须覆盖 FTS/向量/图/缓存；外部知识源只读、选择性抽取。

## 5. 核心流程与状态

### 5.1 知识生命周期状态机

| 状态 | 进入条件 | 允许动作 | 退出条件 | 异常恢复 |
|---|---|---|---|---|
| `REGISTERED` | 来源登记通过（许可/用途/敏感级/校验和齐全） | 导入、解析 | 导入成功 | 校验和缺失→隔离，不得「默认院内可用」 |
| `DRAFT` | 导入+分块完成 | 编辑、元数据、链接 | 提交评审 | 分块失败→重建，不静默丢段 |
| `IN_REVIEW` | 提交评审 | 批准、驳回、补充 | 评审结论 | 评审人无资质→拒绝 |
| `APPROVED` | 评审批准 | 发布、退役 | 发布或退役 | 冲突/过期→不发布为强提示 |
| `ACTIVE` | 发布成功 | 命中、引用、反馈、回退 | 回退或退役 | 检索不可用→保留硬规则并降级 |
| `RETIRED` | 回退/退役/撤回 | 只读、历史引用 | — | 删除传播完成后才能删除派生索引 |

未评审（`DRAFT`/`IN_REVIEW`）、已过期、已撤回的知识**不得**产生强制提示，只能作为历史引用。

### 5.2 检索流程（用户/Agent 共用）

授权范围/用途/时间水位 → 意图路由+术语归一 → 混合召回（Dense/BM25/Exact/Graph depth≤2/SQL 精确）→ RRF 融合 → Cross-encoder 重排 → 权限二次校验+版本/过期校验 → 上下文预算截断 → 返回可寻址 `ContextReference`。

### 5.3 反馈闭环

命中 → 采纳/驳回/纠错 → 反馈记录（绑定用例、患者/就诊、知识版本、来源、结果状态）→ 知识治理队列 → 评审 → 新版本发布/回退。

## 6. 功能需求

> ID 前缀 `KC-FR` 为本模块独立编号，追溯矩阵见 §11；沿用 v1.0 PRD 的 `FR-056`、`FR-070~080` 作为上位需求。

### KC-FR-001 知识中心入口与总览

- 用户/场景：平台中心所有角色进入知识中心。
- 可观察行为：平台中心新增「知识中心」菜单，展示知识资产概览（内容域分布、待评审、已发布、近期命中、反馈、退役预警）。
- 业务规则：`KC-BR-001` 菜单与「数据中心」「AI 中心」并列。
- 验收标准：`KC-AC-001`、`KC-AC-002`。

### KC-FR-002 知识条目编辑（Markdown + 双链）

- 用户/场景：知识库管理员编辑指南/说明书/路径/质控依据条目。
- 可观察行为：Markdown 编辑、双向链接 `[[]]` 自动补全、结构化元数据表单（分类分级/有效期/许可/来源权威/临床标签）。
- 业务规则：`KC-BR-002` 元数据缺许可/用途/敏感级/校验和即隔离；`KC-BR-003` 编辑器用 MIT 组件（CodeMirror6/TipTap），不内嵌 Obsidian 代码。
- 验收标准：`KC-AC-003`。

### KC-FR-003 双向链接与反链

- 用户/场景：知识条目间建立关系；查看某条目的被引用情况。
- 可观察行为：条目内建立链接；查看反链列表（哪些规则/路径/Agent 引用了该知识）。
- 业务规则：`KC-BR-004` 反链至少覆盖「知识条目↔知识条目」「规则↔依据（SUPPORTED_BY）」「Skill/Agent↔知识 release」三类。
- 验收标准：`KC-AC-004`。

### KC-FR-004 知识图谱视图与遍历

- 用户/场景：可视化知识关系；按概念/规则/药品/术语浏览。
- 可观察行为：图谱渲染（Cytoscape.js/AntV G6）、节点/边类型（概念、映射、SUPPORTED_BY、CONSTRAINS）、深度≤2 遍历。
- 业务规则：`KC-BR-005` 禁止开放式图遍历；`KC-BR-006` 术语节点引用主数据字典，不重复建本体。
- 验收标准：`KC-AC-005`。

### KC-FR-005 标签与分类分级元数据

- 用户/场景：给知识打临床标签、设分类分级。
- 可观察行为：标签、`PUBLIC/INTERNAL/SENSITIVE/RESTRICTED` 分级、有效期、许可、来源权威。
- 业务规则：`KC-BR-007` 分级与授权水位联动，召回后二次授权。
- 验收标准：`KC-AC-006`。

### KC-FR-006 全文 + 语义混合检索

- 用户/场景：临床使用者/Agent 检索知识。
- 可观察行为：关键词（FTS）、语义（pgvector）、精确（术语/药品/编码）、图（depth≤2）多路召回，RRF 融合与重排，返回可寻址引用。
- 业务规则：`KC-BR-008` 数值/日期/用药/诊断优先精确检索，禁止用向量猜测；`KC-BR-009` 引用必须含 `source_type/source_id/version/locator/content_hash/authorization_watermark`。
- 验收标准：`KC-AC-007`、`KC-AC-008`。

### KC-FR-007 知识模板

- 用户/场景：按模板新建各类知识条目。
- 可观察行为：指南/药品说明书/临床路径/质控依据/通用模板，约束必填字段。
- 验收标准：`KC-AC-009`。

### KC-FR-008 版本化发布与回退（治理）

- 用户/场景：知识库管理员发布新版本；机构按需回退。
- 可观察行为：不可变版本、内容哈希、语义版本、发布/退役/回退、删除传播证据。
- 业务规则：`KC-BR-010` 未评审/过期/撤回版本不产生强提示；`KC-BR-011` 回退后新命中使用批准版本；`KC-BR-012` 删除传播覆盖 FTS/向量/图/缓存且每个消费者写完成水位。
- 验收标准：`KC-AC-010`。

### KC-FR-009 知识来源登记与许可

- 用户/场景：知识库管理员登记知识来源。
- 可观察行为：`SRC-KNOWLEDGE` 来源登记（许可/用途/敏感级/更新频率/校验和/保留期）。
- 业务规则：`KC-BR-013` 任一缺失进入隔离；未批准不发布。
- 验收标准：`KC-AC-011`。

### KC-FR-010 知识命中/反馈闭环

- 用户/场景：使用者对检索命中做采纳/驳回/纠错。
- 可观察行为：反馈记录绑定用例/知识版本/来源/结果状态，回流治理队列。
- 业务规则：`KC-BR-014` 每个 AI 建议关联知识版本与人工处理结果（延续 BR-028）。
- 验收标准：`KC-AC-012`。

### KC-FR-011 术语/本体引用

- 用户/场景：知识条目的概念归一引用主数据字典。
- 可观察行为：概念映射到主数据术语，展示等价映射/版本/审核人。
- 业务规则：`KC-BR-006`（复用）。
- 验收标准：`KC-AC-013`。

### KC-FR-012 Agent 知识检索联动

- 用户/场景：Agent（摘要/文书/质控/结果闭环/协同）在受控下检索知识。
- 可观察行为：`knowledge_search`/`knowledge_lookup`/`knowledge_graph` 三个 T0 只读 Tool；知识 release 进入 RunScope 快照；结果注入 C4 Evidence 层，不进入 System Prompt。
- 业务规则：`KC-BR-015` Tool 服务端重新鉴权；`KC-BR-016` 检索结果按不可信内容处理；`KC-BR-017` 同一次运行不静默混用新旧知识版本。
- 验收标准：`KC-AC-014`、`KC-AC-015`。

### KC-FR-013 外部知识源只读接入（Obsidian 库）

- 用户/场景：知识库管理员从本地 Obsidian 医学知识库**选择性**导入有用知识。
- 可观察行为：按选择矩阵读取外部库有用数据（`医学结构化数据/图谱详情` 的 Markdown 详情页 YAML+`[[]]` 双链 + 全量制表符 TXT，`知识详情` 的临床有用领域），解析并导入知识中心本库副本；明确排除七巧板医学术语集、HiTA 资源等；原始文件不被创建/修改/删除。
- 业务规则：`KC-BR-018` 外部知识源只读接入，只抽取有用数据、写入本库副本，禁止写回源库；`KC-BR-019` 每条导入记录保留 `source_path + source_content_hash + imported_at` 溯源，源变更以重新导入生成新版本；`KC-BR-020` 抽取/排除选择矩阵在 S005-1 明确，未列入选择矩阵的数据不导入。
- 验收标准：`KC-AC-016`、`KC-AC-017`。

## 7. 验收标准

### KC-AC-001

- Given：平台中心登录；When：打开侧栏；Then：出现「知识中心」菜单且与数据中心/AI 中心并列；验证方式：自动化路由审计。

### KC-AC-002

- Given：知识中心总览；When：加载；Then：展示内容域分布/待评审/已发布/近期命中/反馈/退役预警；验证方式：自动化 + 视觉验收。

### KC-AC-003

- Given：新建指南条目；When：保存；Then：Markdown/双链/元数据生效，许可缺失进入隔离；验证方式：自动化。

### KC-AC-004

- Given：条目 A 被规则 R 引用为依据；When：查看 A 的反链；Then：列出 R（SUPPORTED_BY）及引用版本；验证方式：自动化。

### KC-AC-005

- Given：图谱视图；When：从概念节点遍历；Then：仅返回 depth≤2 的关系，禁止开放式遍历；验证方式：自动化。

### KC-AC-006

- Given：RESTRICTED 知识；When：无授权使用者检索；Then：召回被二次授权拦截；验证方式：自动化 + 安全测试。

### KC-AC-007

- Given：混合检索查询；When：返回结果；Then：每条含可寻址 ContextReference，点击可回表定位到精确 chunk/字段；验证方式：自动化。

### KC-AC-008

- Given：数值/用药查询；When：检索；Then：优先精确/SQL，不向量猜测；验证方式：自动化。

### KC-AC-009

- Given：各模板新建；When：提交；Then：必填字段硬校验；验证方式：自动化。

### KC-AC-010

- Given：同一知识存在有效/过期/未评审/回退版本；When：发布并回退；Then：未评审/过期不产生强提示，回退后命中用批准版本；验证方式：规则/知识版本测试 + 临床评审。

### KC-AC-011

- Given：登记来源；When：缺许可；Then：隔离且不放行；验证方式：自动化。

### KC-AC-012

- Given：命中知识；When：用户反馈；Then：反馈绑定用例/版本/来源/结果状态并回流治理；验证方式：自动化。

### KC-AC-013

- Given：知识概念；When：归一；Then：映射到主数据术语并保留等价映射/版本/审核人；验证方式：自动化。

### KC-AC-014

- Given：Agent 检索知识；When：调用 Tool；Then：服务端二次鉴权、版本锁定、结果注入 Evidence 层；验证方式：契约 + 红队。

### KC-AC-015

- Given：知识升级；When：同一 run 内；Then：不得静默混用新旧知识，升级创建新 run 并展示差异；验证方式：自动化。

### KC-AC-016

- Given：外部 Obsidian 库存在源文件；When：执行导入；Then：源文件 mtime/内容哈希不变、库内生成新版本副本且可溯源到 `source_path`；源变更后重新导入产生新版本；验证方式：自动化（源目录只读校验 + 哈希比对）。

### KC-AC-017

- Given：外部源含七巧板/HiTA 及选择矩阵外的数据；When：执行导入；Then：被排除的数据不进入知识库，导入清单可审计；验证方式：自动化（选择矩阵白名单校验）。

## 12. 版本与发布策略

- 版本切片：P0 先落「外部知识源只读选择性导入 + 来源登记 + 版本治理 + 混合检索 + Agent Tool」纵向切片；图谱/反链随后；反馈闭环与评测最后。

- 灰度/回滚：知识版本化发布天然支持回退；机构级启停开关；影子运行不产生副作用。
- 门禁：`SBOM/签名 → 单元/契约 → 合成端到端 → 安全扫描 → 迁移往返 → AI Evals/红队 → 人工批准`。
- 用户验收：本 PRD 待产品/临床/架构/安全/数据联合评审，评审通过后转 `haonan-s004-hld`（已随本文附初稿）与 `haonan-s005-1-lld-data`。
