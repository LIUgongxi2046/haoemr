# HaoEMR 对标卫宁健康、东软、嘉和美康的 EMR 能力缺口审计

## 0. 审计说明

| 项目 | 内容 |
|---|---|
| 审计日期 | 2026-08-13 |
| 对标对象 | 卫宁健康 WiNEX/EMR V6.0、东软 RealOne/医院信息平台、嘉和美康综合电子病历及相关平台 |
| 当前基线 | `docs/product/prd/2026-08-11-haoemr-v1.0-prd.md` PRD v0.7；Prototype SPEC v0.4 / BUILD v0.3 |
| 证据范围 | 厂商官网、行业协会转载的厂商发布材料、政府采购结果公告；不使用无法核验的销售口径推断具体 UI 或未公开实现细节 |
| 审计目标 | 识别可在真实综合医院使用的 EMR 产品能力缺口，并决定进入 v1.0 P0、P1 或维持非目标 |

> 本文比较的是公开可确认的产品能力面，不是对三家厂商内部版本、实施质量或医院现场应用效果的完整评测。同一名称在不同医院项目中可能由 EMR、HIS、集成平台或第三方系统承载。

## 3. 纳入 v1.0 的缺口

### GAP-001 急诊一体化临床工作域（P0）

必须从“门诊分诊和留观字段”升级为独立的急诊上下文和流程，覆盖院前信息接收、预检分诊、抢救区/诊室/留观、时间关键事件、急诊病历、抢救/护理、输液、检查结果、急会诊、交接班和去向。

### GAP-002 临床路径执行与变异闭环（P0）

需具备路径准入/退出、版本、阶段/日程、医嘱/检查/护理/文书任务包、完成度、变异原因、审批、退出和质量统计；路径不得替代医生判断，也不得无声批量生成生效医嘱。

### GAP-003 专科电子病历能力包（P1）

在不分叉核心代码前提下，提供专科术语、结构化控件、评分量表、专科文书、医嘱集、路径、质控、数据集和 AI Skill 的组合包。v1.0 至少以中医、妇产、口腔和重症四类示范包验证扩展机制，不承诺一次性达到各专科完整生产深度。

### GAP-004 无纸化病案与 CDA 共享文档（P0）

覆盖电子原生文书、外部报告、患者签字纸张/影像、高拍扫描件、CA 证据、格式转换、CDA/共享文档、目录清单、页序、质控、借阅、复制、对外提供和长期验证；任何转换不得丢失原件和来源证据。

### GAP-005 统一临床任务与消息中心（P0）

把危急值、异常结果、会诊、审签、文书时限、路径变异、待执行/待审医嘱、出院整改、数据异常和 Agent 审批统一建模，支持送达、查看、确认、接手、委托、升级、完成、撤回和过期；消息通知不能替代业务终态。

### GAP-006 移动查房与床旁任务（P1）

v1.0 增加响应式 Web/PWA 能力边界：移动查房默认只读总览、任务确认、病程语音/文本草稿、结果确认和会诊意见草稿；给药、输血、医嘱生效、病历签署等仍需设备核验和原高风险确认，不承诺原生 App 或全离线闭环。

### GAP-007 临床资质、诊疗权限与医务授权（P0）

在 RBAC 之上增加执业范围、科室任职、处方权、抗菌药物级别、麻精毒放药品、手术分级、介入/高风险技术、输血、会诊、值班和临时授权；所有判断需基于事件时间和授权版本，过期后不能依靠旧页面继续操作。

## 4. 不纳入或不照搬的内容

- 不因头部厂商具有 HIS 全产品线，就把财务总账、ERP、完整供应链和患者互联网平台全部并入 EMR 内核。
- 不按厂商旧模块边界复制烟囱系统；急诊、路径、病案、消息和专科能力继续复用统一患者、就诊、文书、医嘱、任务、配置和审计内核。
- 不把“有模块”视为质量证据；haoemr 仍以可安装、可恢复、数据一致性、安全门禁和公开测试为 Stable 条件。
- 不用专科包分叉数据库或核心状态机；专科扩展必须是有契约、有版本、有依赖、有回滚的配置/插件制品。
- 不让移动端扩大权限、弱化患者核验或绕过签署、给药和输血等安全流程。

## 5. 对 HaoEMR 的差异化要求

1. 用一套自主临床内核统一门诊、急诊、住院、护理、病案和任务，不复制厂商式模块烟囱。
2. 所有路径、专科包、任务和病案转换规则均配置化、版本化、可测试、可回滚。
3. AI 病历生成、内涵质控、路径建议和专科 Skill 均显示来源、版本和人工控制边界。
4. 发布公开的字段契约、状态机、示例数据、迁移工具和 E2E 证据，使“可用”可被社区复现，而不是只依赖项目交付口径。
